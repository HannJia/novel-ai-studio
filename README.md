# AI Novel Writer

**本地优先的 AI 长篇小说写作软件。**

把灵感对话、剧情规划、正文编辑、知识库和数值记忆放进同一个写作工作台。你可以自己主笔，让 AI 提供建议；也可以让 AI 按设定与规划生成正文，再由你编辑和审查。

[下载 Windows 安装包](https://github.com/HannJia/novel-ai-studio/releases/latest) · [更新日志](CHANGELOG.md) · [反馈问题](https://github.com/HannJia/novel-ai-studio/issues)

> 当前版本：**1.0.3**。项目仍在测试阶段，建议定期使用书架上的“备份项目”。软件不内置 AI 额度，AI 功能需要配置自己的模型服务。

**1.0.3 更新：** 扫描 PDF 视觉识别、暂停与续读、100 MB 资料导入；灵感对话可读取知识库并保存知识条目，书内助手增加软件操作上下文，全局交互中文化。详见 [本次发布说明](docs/releases/1.0.3.md)。

## 下载安装

1. 打开 [Releases](https://github.com/HannJia/novel-ai-studio/releases/latest)。
2. 在 Assets 中下载 `AI-Novel-Writer-1.0.3-x64.exe`，运行安装向导。
3. 首次打开后进入“设置”，添加接口地址、接口密钥和模型名称，测试连接，并分配大纲、写作、审查和对话模型。
4. 回到书架，创建小说，选择写作方式与设定准备方式。

发布的安装包面向 **Windows x64**。普通用户不需要安装 Node.js；GitHub 自动提供的 `Source code` 压缩包是源码，不是安装包。macOS / Linux 暂未提供安装包。

安装包尚未进行代码签名，Windows 可能显示未知发布者提示。请核对下载来源与发布页提供的 SHA-256，不要关闭系统安全防护。更新前先备份项目；浏览器开发版与桌面版的数据不会自动互通，需要通过项目备份导入。

## 软件更新

从 **1.0.2** 开始，Windows 安装版支持检查和安装后续更新：

- 启动约 12 秒后自动检查 GitHub 正式版本，持续运行期间每 6 小时再次检查；可在设置中关闭自动检查。
- 在“设置 → 软件更新”手动检查，查看新版本号、发布日期和更新内容。
- 发现新版时显示可关闭的提示，只有点击“下载更新”后才下载安装包，支持进度显示与取消下载。
- 下载完成后等待你确认“安装并重启”，不会在下载完成或普通退出时自动安装。
- 安装前先保存当前正文、小说、知识库和模型配置；AI 任务、联网对话、后台任务或项目导入未结束时阻止安装，保存失败也不会继续。
- 检查只访问本仓库的公开版本信息，不上传小说或 API Key；下载校验使用发布清单中的 SHA-512。

**1.0.0 / 1.0.1 没有更新功能，请手动安装最新版本。** 浏览器和桌面开发环境不会替换本机软件。无法连接 GitHub 或发布文件不完整时，可以打开发布页手动下载。

发布新版本时，除了 `.exe`，还必须上传同次构建的 `latest.yml`，否则软件不能提供一键下载。完整发布步骤见 [更新发布指南](docs/auto-update.md)。

## 两种写作模式

| 功能 | 写作辅助：作者主笔 | AI 模式 |
| --- | --- | --- |
| 正文创作 | 由你撰写，写作顾问提供思路和资料提醒，不直接改写正文 | AI 生成、续写正文，你可以随时编辑和调整 |
| 灵感与设定 | 灵感对话或自选设定 | 灵感对话或自选设定 |
| 剧情规划 | 大纲、分卷、章节计划、故事弧线、时间线 | 相同 |
| 知识库与记忆 | 可选挂载知识库，使用章节摘要与数据面板 | 相同 |
| 数据提取 | 完成本章或手动扫描，确认后记录变更 | 相同，并参与生成后的处理流程 |
| 审查 | 检查正文的问题，由作者决定修改 | 可按工作流进行检查与有限轮次的修改 |

“谁来写正文”和“如何准备设定”分别选择，灵感模式并不等于 AI 代写。

## 主要功能

### 从灵感到正文

- **书架与项目管理**：多本小说、归档、回收站、项目备份与导入。
- **灵感对话**：讨论故事方向、整理设定，保留最近 5 个创建会话，创建后可在书内查看灵感记录。
- **剧情规划**：管理总纲、分卷规划、章节计划、故事弧线与故事时间线。
- **正文工作台**：章节编辑、字数统计、历史版本、审查结果与 AI 任务状态。
- **模型与规则**：为不同任务分配模型，选择快速 / 均衡 / 严谨工作流，配置可复用的写作技能。
- **导出**：支持小说 TXT、Markdown、EPUB，以及项目备份；项目备份与正文导出用途不同。

### 知识库与长篇记忆

在书架层面创建资料库，手动录入历史事件、世界观、地点、人物等资料，也可以导入 TXT、Markdown、DOCX、EPUB、文字版和扫描版 PDF。

- 生成条目摘要与知识库摘要，可选**简略 / 标准 / 详细**，由 AI 整理分类。
- 每本小说独立选择是否挂载，以及挂载哪些知识库，两种写作模式均可使用。
- 知识库实体在书架层共享维护：多本书挂载同一个库时，会读取同一份资料，并非每本书复制一份。
- AI 上下文优先使用摘要和相关条目，结合总纲、角色、章节摘要与规划数据，不是每次把整本小说全文交给模型。
- 默认提供本地混合检索；可选连接 OpenAI 兼容的 Embedding 服务，补充语义检索。不启用向量服务也能使用写作功能。
- 灵感对话可选择参考哪些书架知识库，默认全部；新小说的挂载范围仍由作者另行确认。书内助手只读取本书挂载的资料。
- 对话中可整理知识条目，点击“存入知识库”预览并编辑，确认后保存到已有库或新建库。助手可回答已接入的软件操作问题。
- PDF 默认直接提取文字层，无文字页面才调用所选模型识图；文字层错误或不完整时可选择整份视觉识别。兼容支持图片输入的 OpenAI 格式聊天接口，沿用现有密钥，不另接 OCR 服务。
- 识别逐页显示进度，支持暂停。重新打开软件后，选择同一文件和读取方式即可复用本机缓存；文件内容变化后会重新识别。识别结束预览并“确认导入”，可选择自动整理摘要。

单个知识库导入文件上限为 **100 MB**，提取文本最多 500 万字符、PDF 最多 1000 页，压缩文档另有解压安全上限。视觉识别会发送页面图片给所选服务商，可能计费；不保证手写、模糊扫描、复杂排版和数字识别完全准确。摘要和检索也可能遗漏细节，重要设定应保留原始资料并人工核对。

### 故事时间与数据面板

适合需要持续记录状态的种田、修炼、游戏与成长类故事。

| 场景 | 支持的记录方式 |
| --- | --- |
| 时间流逝 | AI 从章节中识别明确经过的天数，推进故事时钟；可人工校正 |
| 作物成长 | 根据故事时间和成长规则计算进度，记录额外进度与剩余成熟时间 |
| 新装备 / 道具 | 从正文提取名称、数值、归属和证据，确认后建立记录 |
| 装备加成 | 区分持有与装备中，只有已装备且明确映射的属性参与计算 |
| 角色属性 | 基础数值与装备后的有效数值分开，卸下装备后重新计算 |

例如，基础攻击力为 100，已装备的武器提供固定攻击力 +20，另一项已装备加成提供基础攻击力 +10%，则有效攻击力为 `100 × 1.1 + 20 = 130`，基础属性仍保留 100。

**提取不等于直接写入。** 点击“完成本章”或“扫描变更”后，AI 产生待确认数据，附带正文证据，确认后才纳入正式记录。仅获得装备不会自动加属性；道具使用也要有明确事实依据。条件触发、最终乘区等复杂规则不属于当前通用自动结算范围。

## 数据、隐私与费用

- **本地保存**：桌面版将小说数据库保存在本机用户数据目录；当前没有账户系统或跨设备云同步。
- **AI 请求**：生成、摘要、分析和审查会将对应文本与必要上下文发送到你配置的模型接口；可能产生模型服务费用。
- **扫描 PDF**：明确开始读取后才按需发送页面图片；已完成页的文字缓存保存在本机浏览器 / 桌面应用存储中，不缓存密钥或原始页面图片。缓存不随项目备份迁移，清理应用数据会删除缓存；确认导入后的正文条目会进入项目备份。
- **向量服务**：启用远程 Embedding 后，待索引的记忆资料会发送到对应接口。需要本地处理时，应使用自己的本地服务。
- **API Key**：桌面版使用操作系统安全存储加密；本机开发环境为方便调试使用浏览器持久化配置，不适合共享电脑。
- **开发地址**：`localhost` 与 `127.0.0.1` 的浏览器存储相互独立，请固定使用同一地址。清除浏览器数据也会影响本地资料与配置。
- **备份与迁移**：通过“备份项目 / 导入项目”迁移小说与知识库；API Key 需要在目标设备单独配置。不要把密钥或私人手稿提交到公开仓库。

联网搜索是独立的可选功能，需要模型接口支持对应搜索协议；关闭搜索并不意味着 AI 对话不联网。

## 本地开发

技术栈：**Electron + Vue 3 + TypeScript + Pinia + Naive UI + SQL.js / SQLite + Vite**。

环境要求：Node.js `20.19+`（20.x）或 `22.12+`，以及 npm。此次发布构建使用 Node.js 24。

```bash
git clone https://github.com/HannJia/novel-ai-studio.git
cd novel-ai-studio
npm ci
```

浏览器调试：

```bash
npm run dev:vite -- --host localhost --port 5173 --strictPort
```

打开 `http://localhost:5173/`。桌面开发使用 `npm run dev`，会启动 Vite 与 Electron。

| 命令 | 用途 |
| --- | --- |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm test` | 自动化测试 |
| `npm run build:renderer` | 仅构建前端，不生成安装包 |
| `npm run build -- --win nsis --x64 --publish never` | 在 Windows 上构建 x64 安装包，不自动发布 |
| `npm run test:electron:packaged` | 检查已打包桌面程序的启动与安全隔离 |
| `npm run test:update-download` | 隔离测试真实更新组件的下载与校验，不安装软件 |

安装包输出到 `release/`。依赖、构建产物、本地数据库与密钥文件不应提交到仓库。发布验证结果见 [1.0.3 发布说明](docs/releases/1.0.3.md)。
