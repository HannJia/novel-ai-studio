## 完成内容

### 公式与保存

- `safeFormula.ts` 使用受限解析器，不依赖 JavaScript 动态求值。支持括号、正负数、四则运算、字段引用；带空格等特殊字符的字段名使用 `[字段名]`。
- 公式链可前向引用；未知字段、重复字段、循环依赖、非数字和除零会报错。无效字段保留原值并带错误状态，两个编辑入口阻止保存无效公式。
- 历史上已经保存的错误数值不会在启动时批量改写。打开数据对象「编辑数据」并保存会重新计算；例如 `总周期-已成长` 从旧的 99 天修正为 7 天。
- 小说和知识库使用共享修订号保存器，取代全量 deep watch。每次修改显式标记 dirty，不以毫秒时间戳作为保存完成依据。
- 「立即保存」等待该次调用观察到的版本落盘；关闭/导入 flush 继续排空等待期间到达的新修改。后台自动保存仍使用 1.5 秒防抖。
- 保存失败保留 dirty 和错误，不无限自动重试。顶部持续提示，作者可手动重试，或从书架导出当前内存中的项目备份。

### 备份、导入与恢复

- 备份文件限制 256 MB，校验嵌套数组、必要字段、状态、时间、主要数据表 ID 唯一性、章节序号、知识库引用和正文修订所属章节。快照内容也要通过结构校验。
- 保留指向已删除对象的历史变化/提案，不把正常历史一律当成损坏外键；本轮没有声称验证所有剧情逻辑引用。
- 旧 v1 备份仍可使用。新增可选 `chapterRevisions` 保存待确认 AI 正文草稿，避免备份只含正式正文。
- 导入前排空小说/知识库保存队列，拒绝章节后台任务仍在运行时导入，保存导入前项目恢复点。
- 小说、知识库及正文草稿在单次数据库事务中替换；写盘失败恢复导入前内存数据库，两个 Store 只在完整提交后更新。导入期间屏蔽页面操作。
- 数据库启动执行 SQLite `integrity_check`；读取失败不再静默回退陈旧浏览器缓存或创建空库。无需迁移的健康数据库启动不重写、不无意义轮换备份。
- Electron 使用单实例锁。文件替换增加 fsync 和 Windows 替换失败回滚，避免先删除原文件。

### 资料导入与导出

- 知识文件最大 25 MB；ZIP 最多 2,000 项、单项解压 16 MB、累计解压 64 MB；拒绝 ZIP64、多卷、加密、损坏目录和越界数据。
- DOCX 先有界展开再交给 Mammoth 提取；EPUB 按 container → OPF → spine 阅读顺序提取，不再按文件名字典序。
- PDF 最多 1,000 页，提取文本最多 500 万字符，结束后释放页面/worker；上述限制可能拒绝超大合法资料，可拆分后导入。
- TXT/Word 增加「只导出正文」，保留书名和章节标题/正文，不含简介、分类标签、大纲及统计信息。
- Word 实现统一命名为 `exportToWordHtml`，仍是 Word 兼容 HTML `.doc`，不是原生 DOCX。EPUB 导出目录修复非连续章节序号的链接。

### 本地服务与依赖

- CSP 仅新增 `http://127.0.0.1:11434`、`http://localhost:11434`、`http://[::1]:11434`。自定义其他 HTTP 端口仍受限；服务自身仍需允许客户端请求。
- `@xmldom/xmldom` 定向覆盖到 0.8.15，`fflate` 到 0.8.3；未升级 Vite/Electron 主版本。
- `npm audit`、`npm audit --omit=dev` 均为 0 告警；`npm ci --dry-run --ignore-scripts` 通过。审计结果是本次依赖快照，不保证将来不会出现新公告。

## 恢复指南

### 看到「保存未完成」

1. 先不要退出软件。检查磁盘空间、目录写权限，点击「重试保存」。
2. 错误未消失时，返回书架「备份项目」下载当前项目。备份不以本次数据库保存成功为前提；但仍会做结构校验。
3. 备份不包含 API Key。它包含书稿、资料和对话，请自行保管，分享软件时不要把个人备份一起发出去。

### 启动出现「数据加载失败 · 已停止写入」

1. 不删除用户数据目录。可先「重新加载」，排除临时文件占用或读盘问题。
2. 检测到有效 `.bak` 时，可选择「从有效备份恢复」，确认后执行。备份生成之后的修改可能不在恢复结果中。
3. 「保留原文件并新建空库」只在作者明确确认后执行，不会尝试从坏库自动拼接书稿。
4. 恢复前会给原库和 `.bak` 各保留独立 `.recovery-时间-UUID` 副本。桌面端位于 Electron 用户数据目录、与 `novel-writer.db` 同目录。
5. 浏览器版恢复副本保留在该网站的本地存储；容量不足时会停止恢复，不能用清理网站数据来“解决”，否则书稿也会删除。

### 撤回一次项目覆盖导入

- 桌面端在数据库同目录保存 `novel-writer-before-import.json`；它是最近一次导入前的恢复点，不是无限历史。
- 正常打开软件后，在书架「导入项目」选择该文件，再确认覆盖。操作前也建议把当前项目另行导出，保留两份。
- 浏览器版恢复点为该 origin 的本地存储项 `novel-writer-before-import`，目前没有独立下载按钮；需要通过浏览器开发者工具导出其 JSON，再从书架导入。
- `.recovery-*` SQLite 原件是人工修复用副本，不是 JSON 项目包，不要直接作为项目备份导入。
