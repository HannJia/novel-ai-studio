# 单章篇幅与全文审核

本次优化对应 2026-10-17 调研中的四项优先事项。当前已合入以公开 v1.0.7 为基线的本地分支，保留“墨笺”的界面布局、主题及原有更新地址；版本沿用 1.0.7，仅运行本地开发预览，不发布到 GitHub。本地早先生成的 1.0.6 测试包不代表当前合并结果，现有安装版也不会自动获得这些未发布改动。

## 作者如何使用

编辑器顶部显示当前字数是否达标、差多少／超出多少，以及目标和允许区间。默认最低 2000、目标 2200、最高 2400 字，包含上下边界。点击“篇幅设置”可以按书调整，最低、目标、最高需为 100–20000 的整数且依次不减。

统计沿用已有的去空白后字符长度，包含标点，英文逐字符计；没有重算旧书的历史字数，也没有改动既有正文。这里的“字数”不是 token 数，不承诺与某个投稿平台的口径完全相同。

AI 自动写作模式下，短稿有“生成扩写候选”，长稿有“生成压缩候选”。长稿点击“完成本章”也会先尝试生成压缩候选。候选保留在单独修订记录中，原稿不变；检查调整后的结尾和内容后，作者查看最终差异、确认写入，再完成本章。未达标或输出截断时停止本次调整，保留原稿。

辅助写作模式继续由作者修改正文。可以查看字数缺口和审核意见、调整篇幅设置，系统不会自动重写正文。历史锁定章节可以继续阅读和导航，不会因新默认上限被重写。

## 完成条件

- 总纲、分卷、正文生成、事件篇幅计划、编辑器状态和完成检查使用同一篇幅配置。
- 初稿仍按既有次数上限生成，超过目标也先保留自然结束的原稿，不按字符直接截断；超长草稿提示压缩。
- 内容修正候选必须先满足篇幅范围，再检查结尾和内容；不合格候选不能自动替换原稿。
- 收尾续写可能增加字数；完成流程中的收尾候选若超范围，会先尝试篇幅校准，再复查结尾。
- 待确认候选写入前按当前篇幅设置重验。确认后清除旧审核签名，完成本章时重新检查最终版本。
- 真正完成前和最终定稿前再次检查篇幅。语义结尾检查、硬问题审查、版本保护与原稿快照继续保留。

一次篇幅调整只请求一个正文候选，不自动重试网络请求。质量修正的既有次数上限和正文追加请求上限继续有效；不合格时返回作者处理，不无限循环。作者主动再次点击是新的任务，不承诺每个模型一次就能写到精确长度。

## 审核覆盖

正文上下文不再静默截取前 4000 字符。编辑器、候选复检和列表批量审校共用同一审核服务：

1. 按原文字符位置切为每段最多 3200 字符、相邻重叠约 160 字符的片段，避开 Unicode 代理对边界。
2. 单段只做一次全文审查；长章逐段审查，并要求每段给出不超过 600 字符的事实摘要。
3. 长章再用所有分段摘要核对全章时间、数值、人物状态与事件因果关系。报告明确这是摘要关系复核，不能声称此步骤逐字重读全文。
4. 任意分段有必须修改的问题，汇总不能被其他分段或全章高评价覆盖。解析不明、缺摘要、接口失败、输出截断都算未完成。

每次最多 8 段，实际重叠切片数超过上限时在请求前停止并建议拆章。报告格式不明最多重试一次；接口错误不自动重试。面板显示原文已审段数、已覆盖字符和全章关系复核是否完成，失败记录绑定被审正文／设定签名。完成覆盖表示检查执行完整，不等于正文质量通过，两者分别判断。

审核缓存升级到 `review-v3`，旧报告需要重新验证。复用要求签名、原文长度、全部分段、全部字符与关系复核状态均有效；正文或设定变化后旧结论不能继续放行。列表批量审查是独立的建议性报告，不直接代替完成本章时的本地硬问题和结尾检查。

## 数据兼容

SQLite 增加两个可空字段：书籍的 `chapter_length_policy` 和章节的 `content_review_coverage`。旧数据缺字段时读取默认篇幅；迁移不改正文、不重算字数。既有数据库初始化的迁移备份机制继续生效。

备份导出、导入和 SQLite 往返保留新增设置及合法覆盖记录。持久化加载对覆盖计数、类型、状态组合进行校验；不把损坏的“complete”记录修补成通过。合成旧库迁移测试验证了原稿、状态、历史字数与迁移前备份保持一致。
