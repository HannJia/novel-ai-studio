# 07 · 无障碍与可读性

新版的视觉方案（低饱和宣纸底 + 印章红 + 细线）在无障碍上有三个真实风险：
红色文字对比度、键盘可达性、动效。本文件给出可验证的标准。

---

## 1. 对比度（必须实测，不能目测）

### 1.1 标准

遵循 WCAG 2.1 AA：
- **正文文字**：对比度 ≥ 4.5:1
- **大号文字**（≥ 18px 或 ≥ 14px 粗体）：≥ 3:1
- **UI 组件边界**（输入框边框、按钮轮廓）：≥ 3:1

### 1.2 浅色主题逐项实测表

实现方必须用工具（如 WebAIM Contrast Checker）逐项填入实测值，
下表为**按 `01-tokens.md` 第 1 节的值预先计算的结果**，需要复测确认。

| 前景 | 背景 | 用途 | 计算值 | 判定 |
| --- | --- | --- | --- | --- |
| `#26221E` 正文墨色 | `#FAF8F4` 宣纸 | 正文 | ≈ 13.6:1 | 通过 |
| `#6B635A` 次级文字 | `#FAF8F4` | 次要说明 | ≈ 5.9:1 | 通过 |
| `#9A9188` 三级文字 | `#FAF8F4` | 时间戳、图注 | ≈ 2.8:1 | **不通过 4.5，仅可用于 ≥18px 或非必要信息** |
| `#B03A2E` 印章红 | `#FAF8F4` | 主按钮文字背景、强调数字 | ≈ 5.4:1 | 通过（正文级） |
| `#FFFFFF` 白字 | `#B03A2E` 印章红 | 主按钮文字 | ≈ 5.6:1 | 通过 |
| `#9E2B25` 印章图形色 | `#FAF8F4` | 印章图形（非文字） | ≈ 6.6:1 | 通过（图形） |
| `#C9852B` 待确认 | `#FAF8F4` | 标签底 + 白字 | ≈ 2.6:1 对白字 | **不通过**，见 1.3 |

### 1.3 已知的三个问题及处理

**问题一：三级文字 `#9A9188` 在宣纸底色上只有约 2.8:1。**

处理：
- 三级文字**只用于非关键信息**（时间戳、字数统计、图注）
- 如果用于列表项的元信息（如「第 12 章 · 3 分钟前」），
  改为 `--text-color-secondary`（`#6B635A`）
- **不得**用三级文字承载操作说明或错误提示

**问题二：`--state-pending`（`#C9852B`）上放白字不达标。**

处理：改用**深色文字 + 浅色底**：
- 底：`#FDF3E3`
- 字：`#8A5A14`
- 边框：`#E8C88C`
这样既保持了「待确认」的黄色语义，又满足对比度。深色主题同理反相。

**问题三：「待确认」和「AI 建议」两个状态都用橙色/红色系，色觉障碍用户难以区分。**

处理：**不能只靠颜色区分状态**，必须叠加形状或文字：
- 「待确认」→ 始终带「待确认」文字标签，不只是色块
- 「AI 建议」→ 虚线描边 + 右上角 AI 角标（形状差异）
- 故事地图三种节点：实心 / 空心 / 虚线（形状差异，见 `04-pages.md` 第 5 节）

### 1.4 深色主题

深色主题需要**单独复测**，不能假设浅色通过则深色也通过。
按 `01-tokens.md` 第 2 节的值，主要风险在 `--text-color-tertiary`（`#756C64`）
在 `#1C1917` 上，约 3.4:1 —— 同样只可用于非关键信息。

### 1.5 交付要求

实现方需在 `docs/design/` 下补一个 `contrast-report.md`，
逐项填入实测工具的输出截图或数值。**这是验收项之一**（见 `08-rollout.md`）。

## 2. 键盘可达性

### 2.1 焦点环（统一规范）

现有代码库**没有统一的焦点样式**，浏览器默认的焦点环在宣纸底色上偏蓝、不协调。

统一规范：

```css
:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 2px;
  border-radius: inherit;   /* 让焦点环贴合圆角 */
}
```

要点：
- **必须用 `:focus-visible`**，不要用 `:focus`。鼠标点击不应出现焦点环
- 深色主题下 `--color-primary` 已提亮（`#C9603F`），无需另写规则
- **不要用 `outline: none`** 去掉焦点环而不给替代方案

### 2.2 焦点顺序

- 所有交互元素必须可通过 `Tab` 到达
- 焦点顺序遵循视觉顺序（左侧导航 → 主内容 → 右侧面板）
- 有弹窗/抽屉打开时，焦点**必须被困在弹窗内**（focus trap），
  关闭后焦点返回触发元素
- 命令面板打开时焦点自动落到搜索框

### 2.3 手写组件的键盘支持

效果图中新增的手写组件都需要键盘支持：

| 组件 | 键盘要求 |
| --- | --- |
| 悬浮批注卡 | 可 Tab 到达，`Enter` 采纳，`Delete` 忽略 |
| 故事地图节点 | 方向键在节点间移动，`Enter` 打开详情 |
| 设定板卡片 | 可 Tab 到达，「编辑」「丢弃」可聚焦 |
| 卡片拖拽排序 | **必须有键盘替代**：选中后 `Ctrl + ↑/↓` 移动 |
| 章节树拖拽 | 同上 |

### 2.4 跳过导航

正文编辑器前方需要一个「跳到正文」的跳转链接，
让键盘用户不必 Tab 穿过整个侧栏。

### 2.5 语义标签

- 图标按钮必须有 `aria-label`（现有 `Workspace.vue` 第 96 行已有正确做法：
  `aria-label="导出小说"`，沿用）
- 纯装饰图形用 `aria-hidden="true"`
- 动态更新的区域（保存状态、AI 生成进度）用 `aria-live="polite"`
- 错误提示用 `role="alert"`

## 3. 减少动画

### 3.1 必须响应系统设置

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

这是**唯一允许使用 `!important` 的场景**（见 `01-tokens.md` 第 7 节）。

### 3.2 应用内开关

除系统设置外，设置页需要一个「减少动画」开关（默认跟随系统），
持久化到用户设置。三项一起控制：

1. 面板/弹窗进出动画
2. 批注连线的绘制动画
3. AI 生成的光标闪烁（降级为静态）

**保留**：数值变动的高亮提示降级为一次性变色而非闪烁。

### 3.3 闪烁频率

任何闪烁元素频率必须 ≤ 3 Hz，避免光敏性癫痫风险。
AI 生成中的光标闪烁建议周期 1s（0.5s 亮 / 0.5s 灭）。

## 4. 中文排版可读性

除对比度外，中文长文的可读性还有几个具体要求：

| 项 | 要求 | 理由 |
| --- | --- | --- |
| 行高 | 正文 ≥ 2.0 | 见 `01-tokens.md` 第 3 节 |
| 每行字数 | 正文每行 30–40 个汉字 | 效果图正文栏 720px @ 18px ≈ 38 字，符合 |
| 段间距 | 段间 ≥ 0.5 倍行高（不用首行缩进） | 效果图用段间距而非缩进 |
| 字间距 | 0（不加 `letter-spacing`） | 宋体加字距会破坏版面 |
| 两端对齐 | **不用** `text-align: justify` | 中文两端对齐会产生字间大空隙 |
| 标点 | 使用全角标点，不转换 | 不要把 `，` 转成 `,` |
| 中西文混排 | 中西文之间自动加 1/4 空隙 | 可用 `text-spacing` 或手动处理，**低优先级** |

## 5. 无障碍验收

以下为必测项，写入 `08-rollout.md` 各阶段的验收标准：

1. **对比度**：`contrast-report.md` 中所有文本项 ≥ 4.5:1（大号文字 ≥ 3:1）
2. **键盘**：全程不用鼠标可完成「打开应用 → 打开一本书 → 写作 → 保存 → 切换章节」
3. **焦点可见**：所有交互元素聚焦时焦点环清晰可见
4. **focus trap**：弹窗/抽屉打开时 Tab 不逃逸
5. **屏幕阅读器**：核心流程（打开书、写作、AI 续写采纳）可朗读
6. **减少动画**：开启系统减少动画后，无面板位移、无闪烁
7. **色觉**：用灰度截图检查三个状态（已完成/计划中/AI 建议）仍可区分
8. **IME**：用微软拼音完成 `06-interactions.md` 第 3.4 节的三个测试路径
