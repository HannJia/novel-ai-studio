# 03 · 新旧入口对照与数据职责边界

## 1. 一句话前提

**这次是界面重组，不是数据合并。** 任何一页都不改表结构，不改数据写入路径。

## 2. 数据职责边界（交接红线）

新版「设定集」把三个模块收进同一个入口。**三个模块的数据仍然分开存储。**

| 模块 | 存什么 | 不存什么 | 现有实现 |
| --- | --- | --- | --- |
| **角色库** | 角色概述：姓名、别名、身份、性格、外貌、背景故事、关系图 | 不存会随剧情变化的数值 | `CharacterLibrary.vue` |
| **知识库** | 体系设定：世界观规则、势力、地理、力量体系、资料条目 | 不存角色个人数据、不存数值 | `KnowledgeBase.vue` |
| **数据面板** | 会随剧情变化的数值：等级、属性、持有装备、状态、关系状态 | 不存静态描述性设定 | `DataPanelWorkspace.vue` |

**判定标准**（实现方遇到拿不准的字段时按此判断）：

> 该字段是否会随剧情推进而改变？
> 会变 → 数据面板。不会变、描述「是什么」→ 角色库（针对角色）或知识库（针对世界）。

一个具体例子：角色的「性格：坚毅」进角色库（不会变）；
角色的「攻击力：100」进数据面板（会变）；
「青云宗是南域第一大宗」进知识库（体系设定）。

**效果图第 1 张的人物详情页**给出了三条数据的**组合视图**：
基础属性表 + 装备卡 + 关系图 + 出场事件。
这是**一次读取、三处聚合**的展示，不是把它们存在了一起。
实现时用聚合查询/前端组合，**不要新增合并表，不要迁移现有数据**。

**右侧「来自正文的更新」面板**是现有 `story_state_proposals` 机制的界面化，
审批通过后写入的是**对应模块各自的表**，不是统一表。

### 3.3 重定向策略（必须实现）

**所有旧路由保留，改为重定向到新入口，并携带必要参数。**
理由：用户书签、历史记录、以及应用内可能存在的硬编码链接都会失效。

```
/workspace/:novelId/characters  → /workspace/:novelId/setting?tab=characters
/workspace/:novelId/knowledge   → /workspace/:novelId/setting?tab=knowledge
/workspace/:novelId/data        → /workspace/:novelId/setting?tab=data
/workspace/:novelId/planning    → /workspace/:novelId/storymap
/workspace/:novelId/volumes     → 保留现有二级重定向，末端指向 /storymap
/workspace/:novelId/outline     → /workspace/:novelId/storymap
/workspace/:novelId/chapters    → 见第 5 节裁定后确定
/workspace/:novelId/inspiration → /workspace/:novelId/inspiration 不变（改版）
```

现有 `volumes` 已经用了重定向 + query 的写法（`src/router/index.ts` 第 49–53 行），
**沿用同一写法**，不要引入新机制。

**注意**：重定向不要用 `beforeEach` 全局守卫统一处理，用路由表内的 `redirect`
函数（与现有代码风格一致，也便于单测）。

## 4. 四个需要单独说明的入口

### 4.1 设定集（合并入口）

- 路由挂在工作台内：`/workspace/:novelId/setting`
- 左侧二级导航：人物 24 / 地点 12 / 势力 6 / 物品·装备 18 / 世界规则 9 / 资料库 2
  （数字是效果图占位，实现时取真实计数）
- 顶部面包屑：设定集 › 人物 › 林远
- **资料库**这一项是「本书绑定的知识库」，与全局知识库（4.2）不是同一页

### 4.2 全局知识库 `/knowledge`（保留独立页）

**为什么保留**：知识库**跨书共享**。设定集里只能显示「本书绑定的库」，
全局库的增删改查、绑定关系管理需要一个独立页面，塞进设定集会导致
「在 A 书里删库，影响 B 书」的困惑。

设计要点（需补画，见 `05-missing-pages.md`）：
- 全局知识库列表（所有库 + 被哪些书绑定）
- 库内条目的增删改查
- 与书的绑定/解绑操作，解绑需明确提示影响范围

### 4.3 生成大纲 `/generate/:novelId`

现有独立页面。新版流程是「灵感工作室 → 以此开书 → AI 生成大纲 → 进入工作台」，
但**路由保留**，因为它是可被直接调用的独立流程（创建向导里也会走到）。

入口调整：不再出现在左侧主导航，改为灵感工作室和创建向导的内部步骤。

### 4.4 灵感记录 vs 灵感工作室

这是**两个不同阶段的东西**，不要合并成一个页面：

| | 灵感工作室 | 灵感记录 |
| --- | --- | --- |
| 阶段 | **开书前**，还没建书 | **开书中**，已有书 |
| 形态 | 对话 + 右侧设定板卡片墙（效果图第 6 张） | 归档列表 |
| 数据 | 灵感表（未绑定书） | 灵感表（已绑定书） |
| 入口 | 全局导航「灵感工作室」 | 工作台内 |
| 现有实现 | 新形态 | `InspirationArchive.vue` |

**数据不合并**，共用灵感表但以 `novelId` 是否为空区分。

## 5. 三处待负责人拍板（交接前必须定）

### 5.1 章节列表的归宿

效果图里**没有独立的章节列表页**，章节树只出现在编辑器左栏。
但现有 `/chapters` 页面有独立功能（批量操作、章节元数据编辑、进度查看）。

三个选项：

- **A**：并入故事地图（章节作为故事地图的一行/一个视图切换）
- **B**：只保留编辑器内的章节树，删除独立页
- **C**：保留 `/chapters` 独立页，但从主导航移除，仅通过命令面板和故事地图可达

**建议 C**。理由：批量操作在窄栏里做不了；故事地图的横向画布不适合承载
「重命名 30 个章节」这类任务。C 保留了功能又不增加导航负担。
**实现方默认按 C 执行**，除非本项已被划掉改选。

### 5.2 「文档」和「素材」入口

效果图左侧导航有「文档」「素材」两项，但现有代码里没有明确的对应模块
（`/workspace/:novelId` 下无 documents / materials 视图）。

**需要确认**：
- 这两个入口是新增功能（要做需求），还是映射到现有某个模块（如素材 → 现有素材库）？
- 如果本轮不做，导航里**先不显示这两项**，避免出现死链。

**实现方默认：导航中不显示，等确认后再加。**

### 5.3 「发布」入口

同上，现有代码无对应模块（导出功能在 `Workspace.vue` 里，是导出 TXT/Word/EPUB）。
需确认「发布」是导出功能的入口改名，还是新的发布流程。

**实现方默认：暂不显示，导出仍从现有位置进入。**

## 6. 导航实现方式

新左侧导航与现有 `Workspace.vue` 的侧栏（第 15–137 行，含 `nav-link` / `nav-badge` /
`nav-divider`）**不是同一层**：

- **全局导航**（首页/设定集/创作/大纲/文档/素材/发布 + 设置）：跨书，固定显示
- **工作台二级导航**：书内，进入某本书后显示

**决定**：全局导航作为独立组件抽出（不要继续塞在 `Workspace.vue` 里）。
现有 `Workspace.vue` 的侧栏样式（`.nav-link` 等，第 350–590 行）可复用，
但需要按 `02-components.md` 第 2.4 节加上左侧 2px 选中竖条。

现有侧栏在 768px 断点下有抽屉化逻辑（`variables.css` 第 185–207 行），
但窗口最小 1024px，该断点永不会触发，需按 `06-interactions.md` 重定。
