# 06 · 交互规则

本文件收录需要**先定规则再写代码**的交互。这些是整套方案里技术上最容易做错的部分。

---

## 1. 行内续写建议字（技术难度最高）

### 目标

正文末尾出现灰色建议文字（效果图第 2 张底部），按 `Tab` 采纳写入正文，
按 `Esc` 忽略。

### 问题

**普通 `<textarea>` 做不出这个效果。** textarea 内的文字样式是统一的，
无法只给末尾一段文字加灰色，也无法让建议文字和正文混排。

现有编辑器（`ChapterEditor.vue`）的输入形态需要实现方先核查；
`ChapterReviewSidebar.vue` 中确实有 `<textarea>` 用法（第 42 行附近）。

### 三个方案

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 叠加层** | 保留 textarea，在其上方叠加一个绝对定位的 `<div>`，内容 = 正文 + 灰色建议。textarea 文字色设为透明，叠加层负责显示 | 改动小，保留 textarea 的原生行为（撤销、输入法、选中、滚动） | 两层必须像素级对齐（字体、行高、字间距、内边距、滚动位置）；textarea 滚动时要同步叠加层；textarea 的透明文字会导致选中高亮异常，需处理 |
| **B. contenteditable** | 换成可编辑区域，建议文字作为 `<span contenteditable="false">` 插入 | 天然支持混排样式；批注锚定也需要它 | **要自己实现全部编辑行为**：撤销栈、IME、粘贴净化、光标位置、选区、Tab 键默认行为拦截。这是个大工程 |
| **C. 独立建议块** | 建议文字不放正文内，放在正文下方的独立区域 | 实现最简单 | **与效果图不符**，效果图明确是「正文里的灰色建议字」 |

### 建议

**方案 A 为首选**，理由：
- 写作软件的 undo/redo 和中文输入法是最高频、最不能出错的功能，
  方案 B 从零实现这两项风险过高
- 方案 A 的对齐问题有成熟解法（叠加层用同样的字体、行高、padding、
  `white-space: pre-wrap; word-break: break-word`，滚动位置用事件同步）

**如果实现方实测发现对齐无法做到无感知**（尤其在 125% / 150% 缩放下），
再考虑方案 B，但**必须同时实现**：
- 自定义撤销栈（至少 50 步）
- IME 组合事件处理（见第 3 节）
- 粘贴时净化 HTML（只保留纯文本和换行）

### 采纳行为

- `Tab` 采纳：建议文字转为正文，光标移到末尾，**这一步要能一次 `Ctrl+Z` 撤销**
- `Esc` 忽略：清除建议，光标位置不变
- 生成过程中用户开始输入：**立即停止生成**（不要继续往末尾追加）
- 生成过程中用户滚动或点击别处：建议保留，不自动消失
- 切章/关闭编辑器时有未处理的建议：**直接丢弃，不提示**（建议是可再生成的）

## 2. 页边批注的锚定

### 问题

批注必须锚定到正文的**具体位置**。正文被修改后，锚点会失效或需要跟随移动。
存储纯字符偏移量是不行的——用户在前面插入 100 字，所有偏移量都错位。

### 建议的锚定模型

每条批注存三部分：

1. **锚点文本**：被批注的原文片段（如「苏婉带着一盏灯笼」），建议 10–40 字
2. **前后文指纹**：锚点前 20 字 + 后 20 字的哈希
3. **原始偏移量**：作为定位提示，不作为唯一依据

### 重新定位算法（正文每次变化后运行）

```
1. 用原始偏移量在正文中定位，检查该位置文本是否 == 锚点文本
   命中 → 锚定成功，更新偏移量，结束
2. 未命中 → 全文搜索锚点文本
   恰好 1 处 → 锚定成功
   多处 → 用前后文指纹消歧，选指纹匹配度最高的
   0 处 → 进入失效处理
```

### 失效处理

锚点文本被删改后无法定位时：

- **不要静默删除批注**（用户会以为 AI 的建议凭空消失了）
- 批注移到侧边栏的「已失效批注」分组，显示「原文已修改，此建议可能不再适用」
- 提供「删除」和「修改后重新采纳」两个操作
- 提供「显示原文位置」按钮（如果还能近似定位）

### 性能

正文变化后重跑定位是 O(n) 的全文搜索。**必须防抖**（建议 800ms），
且只在批注数量 > 0 时执行。

### 批注的存储

**批注不落库**（同 `00-scope.md` 术语表）。它们是本次会话的 AI 输出，
重新审查会重新生成。**不要为批注建表**。

## 3. 中文输入法（IME）

这是最容易被忽略、又最容易出 bug 的地方。

### 3.1 通用规则

任何监听 `keydown` 的地方（快捷键、Tab 采纳、Enter 提交、命令面板搜索），
**必须先判断 IME 组词状态**：

```
event.isComposing || composing || event.keyCode === 229
```

现有代码已有正确先例：`src/components/InspirationChat.vue` 第 320–322 行。
**新代码一律复用这个判断，不要另写。**

### 3.2 各处的具体影响

| 场景 | 风险 | 处理 |
| --- | --- | --- |
| 行内续写的 `Tab` 采纳 | 某些输入法用 `Tab` 或数字选字，会把候选字吞掉 | 组词中不响应 `Tab` |
| 命令面板搜索 | 输入拼音时按到 `1`–`7` 会误触命令 | 组词中不匹配快捷键 |
| `Ctrl+S` 保存 | 组词中 Ctrl+S 通常不冲突，但部分输入法占用 | 保留，但组词中延迟到组词结束后执行 |
| `Enter` 提交（各类表单） | 组词确认的回车会误触发提交 | 组词中不响应 |
| `Esc` 忽略建议 | 输入法用 `Esc` 取消组词 | 组词中不响应，让输入法先处理 |

### 3.3 组合事件

除了 `keydown` 的判断，还要监听：
- `compositionstart` → 置 `composing = true`
- `compositionend` → 置 `composing = false`（注意：`compositionend` 可能晚于
  `keydown` 触发，需要额外处理）

### 3.4 测试要求

**必须**用实际的中文输入法（微软拼音）测试以下路径：
1. 在正文末尾有建议字时，用输入法打字 → 不误采纳
2. 在命令面板输入拼音 → 不误触快捷键
3. 组词中途按 Esc → 只取消组词，不忽略建议

## 4. 快捷键表

### 4.1 完整快捷键（新增，需与现有共存）

| 功能 | 快捷键 | 冲突检查 |
| --- | --- | --- |
| 保存 | `Ctrl/Cmd + S` | **已有**（`ChapterEditor.vue:1201`），保留 |
| 触发续写 | `Ctrl/Cmd + Enter` | **已有**（`:1209`，AI 模式下），保留 |
| 关闭/取消 | `Esc` | **已有**（`:1216`），保留 |
| 命令面板 | `Ctrl/Cmd + K` | **无冲突**，新增 |
| 采纳续写建议 | `Tab` | 无冲突（正文内的 Tab 无默认行为） |
| 忽略续写建议 | `Esc` | 与「关闭」共用，**需定义优先级**：先忽略建议，无建议时再执行关闭 |
| 命令面板内跳转 | `Ctrl + 1`–`Ctrl + 7` | Electron 内无冲突，**需实测** |
| 专注模式开关 | 待定，建议 `Ctrl/Cmd + Shift + F` | 需确认不与 naive-ui 冲突 |
| 面板内上下移动 | `↑` `↓` | 无冲突 |
| 面板内确认 | `Enter` | 需 IME 判断（见第 3 节） |

### 4.2 `Esc` 的优先级链

多处都用 `Esc`，必须定义明确顺序（从上到下依次尝试，命中即停）：

1. 命令面板打开 → 关闭面板
2. 有未处理的续写建议 → 忽略建议
3. 专注模式 → 退出专注模式
4. 有打开的弹窗 → 关闭弹窗
5. 都不满足 → 不响应

**这个顺序必须写进代码注释**，否则后续维护会改乱。

### 4.3 冲突检查结论（实测）

现有代码库中的键盘监听实测只有：
- `InspirationChat.vue:320` — `Enter`（含 IME 判断）
- `NovelList.vue:298` — `Enter`
- `ChapterEditor.vue:1201/1209/1216` — `Ctrl+S` / `Ctrl+Enter` / `Esc`
- `Workspace.vue:261` — `Enter`

**结论**：`Ctrl+K` 和 `Ctrl+1`–`7` 无冲突。`Tab` 在正文内无默认行为，可用。

### 4.4 可发现性

- 命令面板自身有入口按钮（编辑页右上角）
- 效果图第 2 张的「Tab 采纳 · Esc 忽略」提示**只在有建议时显示**
- 设置页需要一个「快捷键」查看表（只读即可，本轮不做自定义）

## 5. 窗口尺寸与折叠方案

### 5.1 硬约束

`app-main/main.js`：默认 1280×800，**最小 1024×700**。

### 5.2 关键问题：1024 宽放不下批注栏

写作页三栏需求：章节树 240px + 正文 720px + 批注 260px = 1220px，
**在 1024px 下溢出 196px**。

### 5.3 折叠方案（按宽度分级）

| 可用宽度 | 章节树 | 正文宽 | 批注 | 说明 |
| --- | --- | --- | --- | --- |
| ≥ 1440px | 展开 240px | 720px | 页边悬浮 | 效果图形态 |
| 1200–1439px | 展开 240px | 自适应（最小 640px） | 页边悬浮，允许与正文重叠 | |
| 1024–1199px | **折叠为 48px 图标条** | 自适应 | **收进右侧抽屉**，默认关闭，有批注时显示计数角标 | **本次必须实现** |
| < 1024px | — | — | — | 不可达（窗口最小 1024） |

### 5.4 需要对现有断点做的调整

`src/styles/variables.css` 第 176–207 行现有两个断点：

- `max-width: 1200px` → 侧栏收窄到 100px，页面 padding 减小。**保留，但要调整**：
  新版侧栏折叠后是 48px 图标条，不是 100px
- `max-width: 768px` → 侧栏抽屉化。**在 Electron 里永远不触发**（窗口最小 1024px）。
  建议**删除这个断点**，改为 `max-width: 1100px`（或按 5.3 表的分级）。

**不要保留死代码断点**，会让后续维护者困惑「这段样式到底走不走」。

### 5.5 折叠态的交互要求

- 折叠后图标必须仍可识别（配 tooltip）
- 有未处理批注时，折叠按钮上有角标数字
- 折叠状态**持久化到用户设置**（下次打开保持）
- 1024px 下打开批注抽屉时，**抽屉覆盖正文而不是挤压正文**
  （挤压会让正文窄到不可读）

### 5.6 高度

最小高度 700px。减去顶部信息栏（约 48px）+ 底部操作栏（约 60px），
正文区约 590px —— 约 15 行正文，可接受。

**但弹窗需要注意**：设置页内容较长，最小高度下必须能滚动，
弹窗内的操作按钮**固定在弹窗底部**（不随内容滚动）。

## 6. 其他交互规则

### 6.1 自动保存

- 编辑时防抖保存（现有行为，保持不变）
- 保存状态三态显示（见 `04-pages.md` 第 3 节）
- **切章前强制保存**，不能丢失
- 保存失败：不阻断编辑，但状态条持续红色 + 提示，并在关闭应用时警告

### 6.2 AI 生成的中断与恢复

- 停止生成：保留已生成内容
- 应用意外关闭后重启：**不恢复未完成生成**（内容已在编辑区，用户可继续）
- 生成请求有超时上限，超时后按「生成中断」处理

### 6.3 跨书切换

- 从 A 书切到 B 书时，A 书的未保存内容先保存
- 全局知识库的选中状态**保持**（跨书共享）
- 故事地图的缩放/滚动位置**不保持**（每次进入重置到当前章节位置）

### 6.4 拖拽

- 设定板卡片顺序可拖拽
- 章节树可拖拽排序、可拖拽移动卷
- **拖拽必须有键盘替代方案**（选中后 `Ctrl+↑/↓` 移动），
  无障碍要求见 `07-accessibility.md`
