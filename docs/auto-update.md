# 自动更新与版本发布

## 用户更新

Windows 安装版从 1.0.2 开始支持自动检查和手动检查。1.0.0 / 1.0.1 没有对应代码，需要手动安装一次 1.0.2。只修改 GitHub Release，无法给已经安装的旧程序远程增加更新入口。

默认启动后约 12 秒检查一次；持续运行时每 6 小时检查。发现更新只显示提示，不自动下载。设置页可以关闭自动检查，也能随时手动检查。

下载后由用户点击“安装并重启”。普通关闭软件不会触发安装。AI 任务、联网对话、后台任务、项目导入或保存失败都会阻止安装。浏览器 / 开发环境只展示说明和发布页，不下载或安装桌面更新。

## 维护者发布

1. 使用标准版本号，例如 `1.0.3`。同步 `package.json`、`package-lock.json` 顶层及根包版本，更新 `CHANGELOG.md`、首页版本和对应发布说明。
2. 在 Windows 执行测试和构建：

```bash
npm ci
npm test
npm run test:update-download
npm run build -- --win nsis --x64 --publish never
npm run test:electron:packaged
```

3. 将源码提交上传到本仓库，为该提交创建对应 `v1.0.3` 标签。
4. 先创建 GitHub Release 草稿，上传同一次构建产生的文件：

| 文件 | 用途 |
| --- | --- |
| `AI-Novel-Writer-1.0.3-x64.exe` | 必需，Windows x64 安装包 |
| `latest.yml` | 必需，包含版本、相对文件名、大小和 SHA-512 |
| `AI-Novel-Writer-1.0.3-x64.exe.blockmap` | 构建产生的分块信息；当前版本使用完整下载，不依赖差分下载 |
| `AI-Novel-Writer-1.0.3-x64.exe.sha256` | 供用户手动核对的 SHA-256 文件 |

5. 核对 `latest.yml` 中版本、文件名、大小和 SHA-512 与 `.exe` 一致。不要将旧版 `latest.yml` 搭配新版安装包，也不要在构建后单独替换 `.exe`。
6. 填写更新说明，确认全部附件上传完成后再公开 Release，并设为 Latest。不要勾选预发布。

程序读取公开仓库 `HannJia/novel-ai-studio` 的最新正式 Release，按标准版本比较，只更新到更高版本。发现新版本后，下载清单与安装包固定到该版本标签下，避免检查和下载之间切换到不同版本。

**仅 push 源码或只创建 Git 标签不会触发可下载更新。** 必须发布带正确附件的 Release。缺少清单或安装包时，用户只能打开发布页处理，软件不会尝试安装不完整的版本。

## 安全与测试边界

- 更新检查不需要 GitHub Token，不上传模型密钥或小说资料；公开 API 存在网络与频率限制，出错时可重试或手动下载。
- 下载由 `electron-updater` 执行 SHA-512 校验。当前未配置代码签名，哈希只能验证文件与该发布清单一致，不能替代发布者签名；应保护好 GitHub 账户与发布权限。
- 不关闭系统安全防护，不接受自定义更新仓库、外部安装 URL、预发布、降级或 NSIS Web Installer。
- `test:update-download` 使用隔离本地 HTTP 服务和不可执行的测试内容，验证真实下载器及篡改拦截；不会运行安装程序。
- 自动化状态机测试验证“确认 → 等待保存 → 安装调用”的顺序，以及错误时不调用安装。完整覆盖安装 / 卸载仍应在专用测试设备上验证，不以用户正在使用的数据目录作为测试目标。
