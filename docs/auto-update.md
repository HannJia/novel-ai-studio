# 自动更新与版本发布

## 用户更新

Windows 安装版从 1.0.2 开始支持自动检查和手动检查。1.0.0 / 1.0.1 没有对应代码，需要手动安装一次 1.0.2。只修改 GitHub Release，无法给已经安装的旧程序远程增加更新入口。

当前开发版的“自动更新”默认开启：启动后约 12 秒检查一次，持续运行时每 6 小时检查；发现新版本并校验更新清单后，在后台下载。设置页可关闭自动更新，关闭后仍能手动检查、下载和安装。此前仅自动检查的安装版需更新到包含本次改动的版本，才能获得该行为。

1.0.5 起：检查失败后按 1、5、15、30、60 分钟逐步退避，之后每小时重试；联网恢复、窗口激活、休眠恢复时会检查是否需要补查，失败补查有一分钟节流。关闭自动检查也会关闭这些自动重试。失败会显示可关闭的状态提示；即使新版更新清单暂时获取失败，也会保留已发现的版本和发布页入口，但不会下载未经验证的安装包。原始 1.0.4 安装包仍采用上面的 6 小时间隔。

下载后由用户点击“安装并重启”。普通关闭软件不会触发安装。AI 任务、联网对话、后台任务、项目导入或保存失败都会阻止安装。浏览器 / 开发环境只展示说明和发布页，不下载或安装桌面更新。

下载完成后，左下角显示“更新已准备好”卡片，提供版本、可滚动的更新说明，以及“安装并重启”和“稍后”。卡片不主动打开模态框或抢占输入焦点；“稍后”收起本次提示，设置页仍能安装。安装按钮仍需明确确认，随后先保存内容，再启动安装程序并重新打开软件。关闭自动更新不会中断已经开始的下载，可使用“取消下载”单独停止；检查期间关闭开关则不会开始自动下载。旧版关闭自动检查的本机偏好继续保留。

## 维护者发布

日常源码同步和自动备份使用私有开发仓库 `HannJia/novel-ai-studio-dev`（本地远程名 `origin`）；正式版本继续发布到公开仓库 `HannJia/novel-ai-studio`（本地远程名 `public`）。创建 Release 时显式指定公开仓库；不要根据默认远程推断发布目标。安装包的 `build.publish` 和客户端更新 URL 保持原有公开仓库不变。跨电脑设置见 [开发同步与自动备份](development-sync.md)。

项目约定：用户说“更新 / 上传到 GitHub”时，默认包括源码、Windows 安装包、更新说明及校验文件，并将规范版本号的补丁位增加一（例如 `1.0.4` → `1.0.5`）。用户明确要求仅上传源码、不打包或指定其他版本号时，以该次说明为准；普通开发任务不自动打包发布。

1. 使用标准版本号，例如 `1.0.3`。同步 `package.json`、`package-lock.json` 顶层及根包版本，更新 `CHANGELOG.md`、首页版本和对应发布说明。
2. 在 Windows 执行测试和构建：

```bash
npm ci
npm run prepare:ocr
npm test
npm run test:update-download
npm run build -- --win nsis --x64 --publish never
npm run test:electron:packaged
node scripts/audit-release.cjs
```

3. 将正式版本源码提交显式推送到 `public` 远程（`git push public main`），为该提交创建对应 `v1.0.3` 标签并单独推送该标签（`git push public v1.0.3`）。不要把开发快照分支上传到公开仓库。
4. 先创建 GitHub Release 草稿，上传同一次构建产生的文件：

| 文件 | 用途 |
| --- | --- |
| `AI-Novel-Writer-1.0.3-x64.exe` | 必需，Windows x64 安装包 |
| `latest.yml` | 必需，包含版本、相对文件名、大小和 SHA-512 |
| `AI-Novel-Writer-1.0.3-x64.exe.blockmap` | 构建产生的分块信息；当前版本使用完整下载，不依赖差分下载 |
| `AI-Novel-Writer-1.0.3-x64.exe.sha256` | 供用户手动核对的 SHA-256 文件 |

5. 核对 `latest.yml` 中版本、文件名、大小和 SHA-512 与 `.exe` 一致。不要将旧版 `latest.yml` 搭配新版安装包，也不要在构建后单独替换 `.exe`。
6. 填写更新说明，确认全部附件上传完成后再公开 Release，并设为 Latest。不要勾选预发布。

程序读取公开仓库 `HannJia/novel-ai-studio` 的最新正式 Release，按标准版本比较，只更新到更高版本。发现新版本后，下载清单与安装包固定到该版本标签下，避免检查和下载之间切换到不同版本。

**仅 push 源码或只创建 Git 标签不会触发可下载更新。** 必须发布带正确附件的 Release。缺少清单或安装包时，用户只能打开发布页处理，软件不会尝试安装不完整的版本。

## 安全与测试边界

- 更新检查不需要 GitHub Token，不上传模型密钥或小说资料；公开 API 存在网络与频率限制，出错时可重试或手动下载。
- 下载由 `electron-updater` 执行 SHA-512 校验。当前未配置代码签名，哈希只能验证文件与该发布清单一致，不能替代发布者签名；应保护好 GitHub 账户与发布权限。
- 不关闭系统安全防护，不接受自定义更新仓库、外部安装 URL、预发布、降级或 NSIS Web Installer。
- `test:update-download` 使用隔离本地 HTTP 服务和不可执行的测试内容，验证真实下载器及篡改拦截；不会运行安装程序。
- 自动化状态机测试验证“确认 → 等待保存 → 安装调用”的顺序，以及错误时不调用安装。完整覆盖安装 / 卸载仍应在专用测试设备上验证，不以用户正在使用的数据目录作为测试目标。

## 2026-10-18 本地实施记录

参照用户提供的更新界面，接通“自动检查并后台下载 → 更新就绪卡片 → 安装并重启／稍后”。沿用现有 `autoCheck` 偏好及 IPC，不改公开更新源或发布配置；`electron-updater.autoDownload` 和普通退出自动安装仍关闭，由控制器在清单验证成功并释放检查锁之后发起下载。设置页在检查期间允许关闭开关，网络返回后重新判断偏好，避免继续自动下载。设置页和卡片共用安装确认，保留原有保存握手、AI／项目任务保护。

Sonnet 通过模型团队桥接提供一次候选；主会话审查修正候选中在检查互斥锁内再次等待同一锁的死锁、未导出的类型引用和重复的提示关闭状态，随后本地调试验收。新增自动下载回归在实现前复现三项失败；最终更新状态机、卡片交互、保存保护和应用焦点相关五组测试共 48 项通过，类型检查与生产构建通过。隔离真实下载器的正常内容及篡改拦截均通过，没有运行安装程序。隔离 Electron 启动检查首次在开发页面渲染完成前的 300ms 检查点失败，复查通过；未据此声称验收了完整安装／卸载流程。
