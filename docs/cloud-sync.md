# 云同步指南

1.0.5 新增未成书灵感会话同步、二次密码确认和登录后修改密码。使用跨电脑灵感续聊时，两端都需要升级至 1.0.5；服务端对原客户端向后兼容。

普通界面使用内置的同步服务器地址，不再展示地址或提供编辑入口。已有本机账号绑定继续保留。自建部署需要维护者在源码中配置服务地址并自行构建，不能在普通设置页换服务器。

## 日常使用

云同步是可选功能。注册、登录本身不会开始上传。首次开启自动同步后，先下载并合并云端内容；新电脑不需要先上传才能恢复作品。本机独有的小说、知识库和灵感会话显示在“本机独有内容”中，由作者勾选并点击“将所选内容加入云同步”。未选择的内容留在本机，重启或反复同步也不会自动加入。

作品引用的本机知识库需要一起选择；小说和灵感会话均按此规则检查，上传时先处理知识库。已经同步过的内容继续自动比较版本；同一编号的本机和云端内容不同时保留双方版本，等待作者处理。编辑器打开、有 AI 或项目任务运行、云端下载尚未应用时延后上传，期间不将待上传修改标记为“已同步”。

在另一台电脑登录同一账号并启用同步，在书架或设置页等待“已同步”。离开当前电脑前建议点击“立即同步”并确认状态。没有网络也可以继续写，网络恢复后会重新比较版本。

每次按小说、知识库和灵感会话逐个比较哈希和版本，仅上传变动的文档，不上传本机数据库文件。同步暂停或失败不会删除本地内容。编辑器或创建页面中的远端更新会等到返回书架 / 设置页、AI 任务结束时再合并；自动生成的中间状态不会与云端合并同时进行。

### 同步范围

| 包含 | 不包含 |
| --- | --- |
| 小说设定、正文、历史版本和待确认正文版本 | 模型 API Key、模型配置、Embedding 密钥（通过下文独立配置同步） |
| 大纲、分卷、章节计划、故事弧线、故事事件 | 应用主题（通过独立配置同步）、更新设置 |
| 角色、故事时间、数据面板及待确认变更 | 原始 PDF、图片、DOCX 等上传文件 |
| 书内对话、已成书的灵感存档 | PDF 识别缓存 |
| 最近 5 个未成书灵感会话、草稿、参考知识库选择、搜索开关与已整理上下文 | 正在生成但尚未完成的 AI 回复 |
| 知识库原文、分类、摘要和挂载关系 | 本机 AI 任务列表和检索索引缓存 |

同一个知识库被多本小说挂载时，同步的仍是同一份资料。换电脑后可手动配置模型，也可以单独恢复云端配置。

灵感历史按完整会话保存，不会一条消息生成一条历史。另一台电脑先在书架或设置页完成同步，再进入创建页的灵感模式即可接着聊。同一会话两边同时改动时保留冲突副本，由作者选择，避免错误拼接对话。项目备份也包含这些会话；旧备份没有会话字段时，不清空本机已有会话。

### 冲突与删除

同一份内容在两端都修改时，软件保留双方版本，显示本机 / 云端标题、章节或条目数量和时间，提供导出及选择。选择云端不会悄悄丢掉本机稿件，旧版本保存在“已处理的冲突备份”中。需要逐段合并时，先导出两份，在本机整理后再同步。

冲突以整本书、整个资料库或整个灵感会话为单位，不会自动拼接正文或对话。如果等待处理时云端又变化，会刷新冲突并要求重新选择。云端删除与本机新修改也会产生冲突。

书架回收站状态正常同步；永久删除产生持久删除记录，防止另一台旧设备复活旧稿。冲突备份只在产生冲突的电脑保存，建议另行导出。

### 账号与空间

- 默认服务仅邀请码注册。管理员在设置页创建普通用户邀请码；有效期 7 天，可设置 1～20 次使用。
- 账号为 3～32 位字母、数字、下划线或短横线，首位为字母或数字；密码至少 6 个字符，注册和恢复时需输入两次确认。建议使用更长、不重复的密码。
- 登录后可点击“修改密码”，验证当前密码并输入两次新密码；修改后包括本机在内的所有设备都需重新登录。小说、知识库和原恢复码不受影响。
- 注册时显示恢复码。忘记密码可凭账号和恢复码重置；旧恢复码和所有旧登录会话失效。
- 首次开启后，本机书架绑定账号和服务地址。为了防止作品被传给其他账号，不允许直接换号或更换服务器。迁移应先导出备份，在独立系统用户环境中登录目标服务并导入。
- 每账号默认 100 MiB；单本小说 / 单个资料库最多 50 MiB，含所有同步历史版本。单个资料文件可导入 100 MB，并不表示该文件形成的资料库一定能同步。
- 达到限制不会截断或清空资料。请先导出备份、精简不需要的历史版本，或由自建服务维护者调整并测试配额。不要为了满足限制直接删除唯一稿件。
- 同一账号最多 8 个有效设备会话；登录有效期 30 天。桌面加密保存凭据，浏览器仅在标签会话中保存。

## 云端配置与密钥恢复

“云端配置”独立于作品同步，单独开启。同步模型地址、模型分工、生成参数、Embedding 配置、写作技能和主题，密钥加密后与设置一起更新。服务器须声明 `preferences-v1` 和 `preferences-account-key-v1`；旧服务仍能同步作品，配置面板会提示升级，不把配置写入小说文档充当兼容方案。

正常使用只需登录云账号并开启“启用云端配置”，不设置第二个密码。先检查云端：云端为空时自动上传本机配置，新电脑没有模型时自动恢复云端配置。两端都有不同配置时选择“使用本机配置”或“使用云端配置”，替换前保留加密恢复副本，可从面板导出。

客户端继续使用 WebCrypto PBKDF2-SHA256（600000 次）和 AES-256-GCM，密文绑定服务器、账号与普通设置；加密材料由已登录账号授权取得，只在客户端内存中缓存。服务端使用数据库之外的随机主密钥和 HMAC-SHA256 派生每账号密钥，普通配置及密文保存在 SQLite。这种便捷模式信任服务器运营者，不是端到端加密，管理员持有服务器密钥时能够解密。恢复后桌面版按既有操作系统加密策略保存模型密钥；浏览器预览使用本机开发存储，公开浏览器环境的模型密钥仅保留在会话中。

空闲时每 30 秒后台静默检查，重启或刷新后登录同一账号即可继续，不需要再次解锁配置。无变化时不重新写配置、不显示全屏遮罩、不重建页面；慢网络检查期间可以继续编辑和导航。真正写入配置时保留短暂的任务互斥保护，界面仍不弹全屏遮罩。两端同时修改时停止自动替换；请求期间本机有新编辑也保留并重新比较。损坏记录、账号变化、旧服务器或持久化失败不会放行恢复。

只有以前用独立恢复密码创建的 schema 1 旧备份会显示“升级旧版加密备份”。输入原密码解锁一次后，保留原加密副本并转为 schema 2 账号自动同步；不会尝试猜密码或无提示覆盖旧备份。新账号和已升级账号没有第二密码表单。

## 隐私与备份

默认关闭同步；启用后服务器保存正文等项目数据。使用 HTTPS 传输和账号隔离，密码使用 Argon2id 哈希，服务端仅保存登录令牌的哈希。Windows 客户端使用操作系统安全存储加密令牌，不允许退回明文。云端配置和作品同步都信任服务器运营者，不能称为端到端加密。

**当前不是端到端加密。** 服务器运营者能够读取云端项目及备份。请仅使用可信的同步服务，不要把密码、模型密钥写进作品或资料条目。同步功能不会从模型配置读取密钥，但你主动写进正文的内容属于正文，会同步。

云同步不是历史备份服务。删除和错误修改也可能同步到其他设备，请定期使用书架“备份项目”，保留在其他磁盘。服务的每日 SQLite 一致性备份保留最近 3 份，默认目录 `/var/backups/novel-sync` 位于同一台服务器，不能抵御整机丢失或服务商终止。

## 自建服务

代码在 `server/`，使用 Python 3.10+、FastAPI、Uvicorn、Argon2 和 SQLite。不是 AI 推理服务，不需要显卡。当前是单实例部署，不能把 SQLite 数据目录直接挂到不可靠的共享网络盘。

部署文件针对 Ubuntu、Nginx、systemd 和挂载到 `/srv/novel-data` 的数据盘。必须为自己的地址申请证书。现有安装脚本仅适用于隔离主机，不可直接用于同时承载 Maibot 或其他业务的服务器。

### 准备步骤

1. 独立确认 SSH 主机指纹，使用密钥登录，保留控制台恢复途径。安装系统安全更新；防火墙仅开放 SSH、HTTP 验证端口和 HTTPS。
2. 将数据盘持久挂载到 `/srv/novel-data`，核对磁盘 UUID，禁止格式化已有数据盘。服务要求挂载点存在，不会在挂载失败时误写系统盘。
3. 将 `server/` 复制到 `/opt/novel-sync/app/server/`，安装 `python3-venv`、Nginx 和 fail2ban。
4. 为自己的域名或公网 IP 配置可信 HTTPS。当前部署使用支持 IP 地址及短期证书的 Certbot，证书名 `novel-sync`，HTTP 验证目录 `/var/www/html`；服务不使用自签名证书或跳过证书校验。
5. 确保 `/opt/novel-certbot/bin/certbot`、`/etc/letsencrypt/live/novel-sync/` 存在，核对 `server/deploy/nginx.conf` 的端口和证书配置。仅在隔离主机上运行 `sh server/deploy/install.sh`。
6. 初次安装自动启用服务；更新服务端代码后额外执行 `systemctl restart novel-sync`。确认 `https://你的地址/v1/health` 返回协议 1。

`server/deploy/install.sh` 会解除 `/etc/nginx/sites-enabled/default` 链接，启用自身的 `default_server`，然后重载 Nginx；它还会写入独立 systemd 单元并重启 Fail2ban。虽然不删除默认站点的原配置文件，这些操作仍可能中断同机其他业务。共用主机部署前必须先做只读盘点，并使用经过单独审查、不会禁用或覆盖其他站点/服务的部署步骤。

`server/deploy/ssh-key-only.conf` 是可选的 SSH 加固示例，安装脚本不会自动启用它。先用另一个终端确认密钥登录成功、服务商控制台可用于恢复，再安装到 `/etc/ssh/sshd_config.d/00-novel-sync-key-only.conf`，运行 `sshd -t` 检查并重新加载 SSH。不要在未验证密钥时关闭密码登录。

### 管理员与配额

首次管理员账号通过本机命令生成的一次性邀请注册：

```bash
cd /opt/novel-sync/app
sudo -u novel-sync /opt/novel-sync/venv/bin/python -m server.manage \
  --data-dir /srv/novel-data/cloud invite --admin --uses 1
```

输出是敏感邀请码，不要写入仓库、日志、发行说明或公开截图。管理员账号注册后可以在软件中创建普通邀请。

默认服务单账号 100 MiB、300 个注册账号上限；示例 systemd 配置将所有账号的有效项目总量限制为 4 GiB，为 WAL、备份和系统文件留出空间。不是每个账号都能同时用满配额。服务拒绝超限写入，本地数据保留。可通过 `SYNC_MAX_USERS` / `SYNC_GLOBAL_QUOTA` 调整总量，单账号配额保存在 `users.quota` 字段。调整前评估磁盘、备份、内存和带宽，不能仅修改客户端提示。

账户端点有限流，单账号每小时最多 600 次文档写入请求。正常 30 秒同步一次约为每小时 120 次检查，无变化不写入；连续更改大量资料时应留意限流提示。

### 备份、恢复与证书

```bash
systemctl status novel-sync nginx fail2ban
systemctl list-timers novel-cert-renew.timer novel-sync-backup.timer
systemctl start novel-sync-backup.service
/opt/novel-certbot/bin/certbot renew --dry-run --run-deploy-hooks
```

`novel-cert-renew.timer` 每天两次检查续期；不要关闭端口 80 的 ACME 验证路径。证书为短期证书，必须监控续期失败。IP 更换需要重新配置证书、Nginx、客户端地址和账户迁移。

每日备份使用 SQLite backup API 生成一致性快照，校验后 gzip 压缩。启用账号自动配置同步后，同一备份还会生成私密的 `<快照文件名>.preferences-key` 配套主密钥文件，权限 600，与数据库快照一起保留最近 3 组。必须把这一对文件一起安全备份；不要上传到 GitHub 或只保存 SQLite。主密钥在数据目录为 `preferences-master.key`，密钥缺失、损坏或与数据库校验记录不匹配时停止配置密钥服务和备份，不自动生成新密钥覆盖旧密文。

恢复时停止 `novel-sync`，备份当前数据库、WAL/SHM 和主密钥，再把校验通过的快照及配套密钥分别恢复为数据目录内的 `sync.sqlite3`、`preferences-master.key`，恢复 `novel-sync` 用户权限和主密钥 600 权限后启动服务。不要在进程运行时直接覆盖 SQLite 文件；旧版不含账号自动加密数据的快照无需配套密钥。

客户端检测到云端版本回退会停止同步，避免把服务器旧快照当作最新稿。遇到回退不要删除本机资料或同步基线，请先导出各设备备份，由维护者协调恢复或在独立环境重新建立数据集。

建议另设异地备份并定期演练恢复。续费服务器、监控容量、更新系统和保证证书续期是持续运维工作，不会因软件发布自动消失。

# 统一模型配置的兼容说明（2026-10-18）

模型配置可选字段 `kind` 为 `chat` 或 `embedding`，省略时仍按聊天模型处理。任务分配新增可选 `embedding`，仅能引用向量模型；大纲、写作、审查、对话仅能引用聊天模型。普通聊天配置上传时省略冗余的 `kind: chat` 与空向量任务，保留旧服务端兼容性。

含向量模型的配置需要配套更新 `server/preferences.py` 的字段校验，继续沿用原有账号、加密包、CAS 和存储协议。旧版服务端会拒绝新字段并保留已有记录，不会因此覆盖云端配置。本轮仅实现并验证本地配套代码，未部署服务端、打包或发布。
